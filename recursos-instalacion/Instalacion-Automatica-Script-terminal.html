Instalación Automática con Script

Deja el entorno Java Web (JDK 17 + Maven + Tomcat + VS Code) listo en una máquina, usando instalar-entorno-java-web.ps1 en vez de los pasos manuales.

📄 instalar-entorno-java-web.ps1 📦 Carpeta de recursos (GitHub) 🖐 Guía manual
01

Chequear la carpeta y copiarla a C:\

Chequear que la carpeta recursos-instalacion (en el USB o la red) tenga todo esto, incluyendo el script:

  • apache-maven-3.9.10\
  • apache-tomcat-10.1.x\
  • El instalador .msi del JDK 17 (Eclipse Temurin)
  • VSCodeSetup*.exe (instalador de sistema de VS Code)
  • La carpeta extensions\ con todos los .vsix
  • La carpeta demo17\ ya descomprimida (no un .zip)
  • instalar-entorno-java-web.ps1 — el script va dentro de esta misma carpeta

Copiar toda esa carpeta al disco C:\ de la máquina, por ejemplo a C:\recursos-instalacion.

02

Abrir PowerShell como Administrador

Clic derecho sobre el ícono de PowerShell (o buscarlo en el menú Inicio) y elegir Ejecutar como administrador. El script lo exige porque instala software y toca variables de entorno del sistema.

03

Ubicarse en la carpeta

Esta ventana elevada arranca en otra carpeta por defecto — moverse a C:\recursos-instalacion:

cd C:\recursos-instalacion
04

Permitir la ejecución de scripts

Solo la primera vez que la máquina corre un .ps1. Habilita la ejecución únicamente para esa ventana, sin cambiar la configuración permanente:

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
05

Ejecutar el script

Opción A — instalación normal

.\instalar-entorno-java-web.ps1 -RecursosPath "C:\recursos-instalacion"
+ EJECUTARDEMO

Opción B — instalación + demo automático

Compila y levanta Tomcat automáticamente al final, sin pasos manuales.

.\instalar-entorno-java-web.ps1 -RecursosPath "C:\recursos-instalacion" -EjecutarDemo

Si se omite -RecursosPath, el script usa D:\recursos-instalacion por defecto.

06

Responder la pregunta de vs_workspace

El script pregunta dónde crear la carpeta vs_workspace. Escribir una ruta o presionar Enter para usar Documents. El proyecto demo17 se copia adentro.

07

Revisar la salida y probar el demo

Al final el script muestra las versiones de java y mvn detectadas.

CON -EjecutarDemo

Tomcat ya queda corriendo (Ctrl+C para detenerlo). Abrir http://localhost:8080/demo.

SIN -EjecutarDemo

¿Dónde correr estos comandos? No en la ventana de PowerShell que usaste para instalar — hay que abrir otra terminal (puede ser sin permisos de administrador) parada exactamente adentro de la carpeta demo17 que quedó dentro de vs_workspace. La forma más simple: abrir esa carpeta con VS Code (Archivo > Abrir carpeta...) y usar su terminal integrada (Ctrl + ñ), que arranca ya ubicada ahí.

cd C:\Users\TuUsuario\Documents\vs_workspace\demo17
mvn clean package
mvn cargo:run

(Reemplazar la ruta del cd por la que elegiste en el paso anterior). Luego abrir http://localhost:8080/demo.

⚠ SI ALGO FALLA

Puerto 8080 ya en uso

Puede pasar si quedó un Tomcat colgado de un intento anterior. Liberar el puerto antes de volver a correr mvn cargo:run:

Get-NetTCPConnection -LocalPort 8080 -State Listen -ErrorAction SilentlyContinue | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
