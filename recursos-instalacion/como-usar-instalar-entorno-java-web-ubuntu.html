Cómo usar instalar-entorno-java-web-ubuntu.sh

Deja el entorno Java Web (JDK 17 + Maven + Tomcat + VS Code) listo en una máquina Ubuntu, usando instalar-entorno-java-web-ubuntu.sh en vez de instalar todo a mano.

📄 instalar-entorno-java-web-ubuntu.sh 📦 Carpeta de recursos (Drive) 🖐 Anexo instalación manual
01

Preparar la carpeta recursos-instalacion-ubuntu

Armar esa carpeta (en el USB o la red) con todo junto, incluyendo el script:

  • apache-maven-3.9.10/
  • apache-tomcat-10.1.x/
  • El .tar.gz del JDK 17 (Eclipse Temurin, Linux x64)
  • code_*.deb (instalador oficial de VS Code para Debian/Ubuntu)
  • La carpeta extensions/ con los .vsix
  • La carpeta demo17/ ya descomprimida (no un .zip)
  • instalar-entorno-java-web-ubuntu.sh — el script va dentro de esta misma carpeta
02

Copiar la carpeta y darle permiso de ejecución al script

Copiar toda la carpeta recursos-instalacion-ubuntu (con el script adentro) desde el USB o la red a la máquina, por ejemplo a ~/recursos-instalacion-ubuntu. Luego, en una terminal:

cd ~/recursos-instalacion-ubuntu
chmod +x instalar-entorno-java-web-ubuntu.sh

chmod +x le da permiso de ejecución al archivo — sin esto, la terminal se niega a correrlo aunque tengas sudo.

03

Ejecutar el script con sudo

Como ya estás parado dentro de ~/recursos-instalacion-ubuntu, --recursos apunta a esa misma carpeta.

Opción A — instalación normal

sudo ./instalar-entorno-java-web-ubuntu.sh --recursos ~/recursos-instalacion-ubuntu
+ --EJECUTAR-DEMO

Opción B — instalación + demo automático

Compila y levanta Tomcat automáticamente al final, sin pasos manuales.

sudo ./instalar-entorno-java-web-ubuntu.sh --recursos ~/recursos-instalacion-ubuntu --ejecutar-demo

Si se omite --recursos, el script busca en /media/$USER/recursos-instalacion-ubuntu por defecto (típico punto de montaje de un USB).

04

Responder la pregunta de vs_workspace

El script pregunta dónde crear la carpeta vs_workspace. Escribir una ruta o presionar Enter para usar el home del usuario. El proyecto demo17 se copia adentro.

05

Revisar la salida y probar el demo

Al final el script muestra las versiones de java y mvn detectadas.

CON --ejecutar-demo

Tomcat ya queda corriendo (Ctrl+C para detenerlo). Abrir http://localhost:8080/demo.

SIN --ejecutar-demo

Entrar a la carpeta demo17 dentro de vs_workspace y correr a mano:

mvn clean package
mvn cargo:run -Dtomcat.home=/opt/apache-tomcat-10.1.x

Luego abrir http://localhost:8080/demo. El -Dtomcat.home es necesario porque el pom.xml trae por defecto otra ruta absoluta distinta a esta.

⚠ SI ALGO FALLA

Puerto 8080 ya en uso

Puede pasar si quedó un Tomcat colgado de un intento anterior. Liberar el puerto antes de volver a correr mvn cargo:run:

sudo fuser -k 8080/tcp

Si fuser no está instalado: sudo apt install psmisc, o como alternativa: sudo lsof -i :8080 para ver el PID y después sudo kill -9 <PID>.
